# 通信のポリシーと承認

[English](../network-policy.md)

サンドボックスの通信は **既定ですべて拒否** されます ([ADR 0008](../../adr/0008-default-deny-network-with-policy-advisor.md))。新しいサンドボックスが通れるのはテンプレートとプリセットで許したものだけです。ほかは規則を承認するまで止められます。

## 規則の提案

Iwato はすべてのサンドボックスで OpenShell の Policy Advisor を有効にします。エージェントは通信が要ると、必要な最も狭い規則を提案します (サンドボックスの `/AGENTS.md` と Policy Advisor の手引きがやり方を伝えます)。OpenShell も止めた通信から提案を作ります。提案はサンドボックスの「ポリシー」タブで待ち、タブに印、画面のタイトルに承認待ちの件数が出ます。Iwato を使っていないときはプッシュ通知でお知らせします (1 分以内に続いた提案は 1 つにまとめます。[通知](terminals.md))。

## 「ポリシー」タブ

タブの上の切り替え (スクロールしても上に残ります) で「一覧」と「YAML」を選びます。選んだほうはブラウザーが覚えます。サンドボックスのポリシーは Iwato が履歴とともに持ちます ([ADR 0022](../../adr/0022-iwato-owns-the-sandbox-policy.md))。提案は OpenShell のものです。一覧:

- **「承認待ち」**: 待っている提案 (エージェントのものが先)。その横 (スマホでは下) に 1 つを開きます ([承認する](#承認する))。「まとめて却下」で、確認のうえすべて却下します
- **「承認一覧」**: サンドボックスの有効なポリシー。承認した提案の規則は「取り消す」で取り消せます。自分の宛先を持つプロファイル (OpenShell の CLI で取り込んだもの) のプロバイダーの規則は読み取り専用です。宛先にプロバイダーの認証情報を付けた規則には「認証情報: 名前」の印が付きます。検査する宛先には、監査モードで通したリクエストと止められたリクエストを出します (サンドボックスのログの最後の 2,000 行から)。止められたメソッドやパスは提案にならないためです
- **「却下した提案」**

ほかに「規則を追加」(承認と同じく、すべてのプログラムに許可します)、規則への「宛先を追加」「メソッドとパスを追加」、規則の部分ごとの削除、プロバイダーの認証情報の宛先のホストへの宛先での「名前 のトークンを付ける / 外す」、「履歴」(変更ごとに理由と差分。「取り消す」で 1 つを新しい変更として取り消せます。最初の版は除きます)、「プリセット」があります。

Iwato の外 (`openshell` の CLI など) でポリシーが変わると、帯で知らせます。「取り込む」でその変更を Iwato のポリシーに入れ、「Iwato の版で上書き」で Iwato の版に戻します。選ぶまで「ポリシー」タブからの変更は待ちます。ほかの画面からの変更 (プロバイダーを付ける、作り直すなど) は先に取り込みます。

ほかでの決定 (`openshell` の CLI など) は 1 分以内に出ます。

### YAML でポリシーを編集する

「ポリシー」タブの「YAML」で、サンドボックスの規則 (`network_policies`、プリセットと同じ形式) をタブいっぱいに出して、まとめて編集できます。適用していない編集は「一覧」に切り替えて戻っても残ります (「YAML」に「未保存」と出ます)。「YAML」を出しているあいだ、「一覧」には承認待ちの提案の数が出ます。「変更を確認」で YAML を確かめ、追加・削除・変更される規則を出します。「適用」で書いたとおりのポリシーになります。サンドボックスの作成時に決まる設定 (`filesystem_policy`、`landlock`、`process`) はその下に畳んで、読み取り専用で出ます。動いているサンドボックスでは OpenShell が変えないためです。プロバイダーの規則は YAML に入りません。

次のときは保存しません:

- YAML を読めないとき、追加・変更した規則が足りないとき (どの規則にも `endpoints` と `binaries` が要ります)
- 宛先がほかの規則やプロバイダーの規則と食い違うとき (OpenShell が拒否します)
- 読み込んだ後でポリシーが変わったとき (承認など。変わるとすぐ編集画面に出ます)。「読み込み直す」で今のポリシーを編集してください。編集していなければ自動で読み直します

保存の間に OpenShell で直接 (CLI など) 変えた分は、上書きされることがあります。そのときはタブに出ます。

プロバイダーの認証情報に結び付いた規則は、プログラムを変えられません。

承認した提案は承認済みのまま、プリセットも一覧に残ります。あとでプリセットを外すと、プリセットが入れたままの規則だけを外します。

## 承認する

開いた提案には、エージェントの理由 (OpenShell の下書きにはありません)、宛先、OpenShell が要求を検査するか、提案したプログラム (参考です。承認した規則はすべてのプログラムに許可します。[ADR 0022](../../adr/0022-iwato-owns-the-sandbox-policy.md)) が出ます。

- **許可する内容**: メソッドとパスごとのチェック。外したものは承認に含めません。検査しない提案 (L4。OpenShell の下書きの多く) は、すべてのパスへのメソッドを並べて `GET` と `HEAD` だけをチェックした状態で開き、チェックしたメソッドを検査つきで許す規則として承認します。最後の行は代わりに検査せずにすべてを通します (Web のポートでなければ最初からチェックします)
- **確認が必要なこと**: 警告です。承認を止めはしません。赤: Cloudflare のフィルター付きリゾルバー (1.1.1.2) がマルウェアかフィッシングとするドメイン、任意のデータを受け取ったり公開したりするサービス (webhook.site、リクエストを受けるサービス、ngrok などのトンネル、外部通信のテスト用ホスト、貼り付けサービス、ファイル置き場)。黄: 登録から 30 日未満のドメイン (RDAP)、検査しない規則、すべてのパスやワイルドカードのホストへの書き込み、内部アドレス (`allowed_ips`)、宛先を広げる設定、Iwato が動くマシンのループバックに届く宛先。どれもなければ分かったことを出します。ホストは Iwato が動くマシンから短い時間切れで調べ、答えを数時間覚えます。調べられなければ「不明」と出ます
- **名前 のトークンを付ける**: 承認する宛先が、プロバイダーの認証情報を付けた宛先から要求を引き取るとき (最初から付けます。GitHub の `github.com` の下への `git push` など)、または付いているプロバイダーの認証情報の宛先のホストのとき (最初は付けません) に出ます。[プロバイダー](providers.md)
- **ポリシーの差分 (YAML)**: 承認で入る規則を、書かれるとおりに
- **却下** (理由は任意。エージェントに伝わります) か **承認**

Iwato 自身のポートへの規則は、承認、手で追加する規則、YAML エディターのどれからでも拒否します。OpenShell が拒否する規則 (同じホスト・ポート・パスで設定が食い違う宛先) なら、開いた提案に理由が出て、承認できません。承認は表示した版に対するものです: その間に提案が変わったときは拒否し、新しい版を出します。

Iwato が表示しきれない提案 (規則が 128 個を超えるものなど) や表示しない設定 (GraphQL、MCP、要求の署名) を含む提案は、絞ったときだけ承認できます。却下するか、YAML で規則を書いてください。

却下した提案は「却下した提案」からあとで承認できます。提案どおりだけです (OpenShell は承認待ちの提案しか編集しません)。

## テンプレート

新しいサンドボックスは、作成フォームで選んだテンプレートから始まります。テンプレートは Iwato のプリセット (下記) に名前を付けたまとまりです。フォームではそのプリセットに印が付き、ほかのプリセットも足せます。

| テンプレート | プリセット |
|---|---|
| 「開発用」(既定) | 「パッケージと Claude Code・Grok Build・Codex のダウンロード」 |
| 「調査用」 | 「パッケージと Claude Code・Grok Build・Codex のダウンロード」「よく読む参照先」 |
| 「なし」 | なし。宛先はすべて提案から承認します |

サンドボックスのポリシーの履歴の最初のコミットに、テンプレートの名前が入ります。

## プリセット

プリセットは名前の付いた規則のまとまりです。作成フォームで選ぶか、あとから「ポリシー」タブの「プリセット」で「入れる」「外す」ができます。外すと、プリセットが入れたままの規則だけを外します。作り直しても残ります。なくなったプリセット (Iwato から外されたもの、消した自分のファイル) には「プリセットが見つかりません」と出ます。その規則はふつうの規則としてポリシーに残り、「外す」は一覧から外すだけです。

Iwato のプリセット:

| プリセット | 許すもの |
|---|---|
| 「パッケージと Claude Code・Grok Build・Codex のダウンロード」 | どのプログラムからも読み取りだけ (GET・HEAD・OPTIONS と、読むだけの POST: npm の audit、レジストリーのトークン、mise の版の問い合わせ): npm、PyPI (uv の Python も)、crates.io、Rust のツールチェーン (rustup)、Go のプロキシ、RubyGems、mise、Node.js と Go の本体、GitHub (github.com、api.github.com、リリース・アーカイブの転送先と raw)、Docker Hub と ghcr.io のイメージ。公開・アップロードは通りません。エージェントのインストールと更新: Claude Code (downloads.claude.ai、platform.claude.com)、grok (x.ai、storage.googleapis.com)、Codex (GitHub のリリース) |
| 「よく読む参照先」 | どのプログラムからも読み取りだけ (GET・HEAD): Wikipedia (英語・日本語・画像)、arXiv (export.arxiv.org も)、MDN、docs.python.org、go.dev と pkg.go.dev、doc.rust-lang.org と docs.rs、nodejs.org、docs.ruby-lang.org と ruby-doc.org、GitHub Docs、man7.org、rfc-editor.org、`*.readthedocs.io`、Stack Overflow、Hacker News |

プリセットは認証情報を付けません。エージェントの API はプロバイダーとともに付きます。プリセットの規則はどのプログラムにも許します ([ADR 0022](../../adr/0022-iwato-owns-the-sandbox-policy.md))。パッケージのプリセットは github.com と api.github.com を認証情報なしで読みます。GitHub のプロバイダーを付けると、そのトークンで読みます。

### 自分のプリセット

「ポリシー」タブの「プリセット」で、自分のプリセットを追加・編集・削除できます (「新しいプリセット」「YAML を編集」「削除」)。設定フォルダーの `presets/*.yaml` に保存し、一覧を開くたびに読み直すので、ほかのエディタで直しても構いません。読めないファイルは理由を出します。自分のプリセットの ID は `user:ID` になるので、Iwato のものを隠しません。

形式は OpenShell のポリシーの YAML の `network_policies` に、`id`・`label`・`note` と、任意の `params` を足したものです:

```yaml
id: my-preset
label: 自分のプリセット
note: 説明
params:                  # 任意。${repo} で使う
  - name: repo
    label: リポジトリ
    placeholder: OWNER/REPO
    pattern: '[A-Za-z0-9-]+/[A-Za-z0-9._-]+'
network_policies:
  allow_example_com_443:
    endpoints:
      - { host: example.com, port: 443, protocol: rest, enforcement: enforce, access: read-only }
    binaries: [/usr/bin/curl]
```

保存のときに、プロバイダーの規則と食い違わないことを確かめます。すべてのホストへの通信を許すプリセットは作れません。OpenShell はホストの `*`・`**` を受け付けず、ホストなしの `allowed_ips` の規則はほかの規則やプロバイダーと同じポートで食い違うためです。
