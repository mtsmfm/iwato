# 通信のポリシーと承認

[English](../network-policy.md)

サンドボックスの通信は **既定ですべて拒否** されます ([ADR 0008](../../adr/0008-default-deny-network-with-policy-advisor.md))。新しいサンドボックスが通れるのはプリセットで許したものだけです。ほかは規則を承認するまで止められます。

## 規則の提案

Iwato はすべてのサンドボックスで OpenShell の Policy Advisor を有効にします。エージェントは通信が要ると、必要な最も狭い規則を提案します (サンドボックスの `/AGENTS.md` と Policy Advisor の手引きがやり方を伝えます)。OpenShell も止めた通信から提案を作ります。提案はサンドボックスの「ポリシー」タブで待ち、タブに印、画面のタイトルに承認待ちの件数が出ます。Iwato を使っていないときはプッシュ通知でお知らせします (1 分以内に続いた提案は 1 つにまとめます。[通知](terminals.md))。

## 「ポリシー」タブ

タブの上の切り替え (スクロールしても上に残ります) で「一覧」と「YAML」を選びます。選んだほうはブラウザーが覚えます。一覧は OpenShell のデータだけを出し (Iwato は何も保存しません)、三つあります:

- **「承認待ち」**: 待っている提案。「承認する」か「却下」
- **「承認一覧」**: サンドボックスの有効なポリシー。承認した提案の規則は「取り消す」で取り消せます。自分の宛先を持つプロファイル (OpenShell の CLI で取り込んだもの) のプロバイダーの規則は読み取り専用です。宛先にプロバイダーの認証情報を付けた規則には「認証情報: 名前」の印が付きます。検査する宛先には、監査モードで通したリクエストと止められたリクエストを出します (サンドボックスのログの最後の 2,000 行から)。止められたメソッドやパスは提案にならないためです
- **「却下した提案」**

ほかに「規則を追加」、規則への「宛先を追加」「メソッドとパスを追加」、規則の部分ごとの削除、「履歴」(プロバイダーの規則は含みません)、「プリセット」があります。

ほかでの決定 (`openshell` の CLI など) は 1 分以内に出ます。

### YAML でポリシーを編集する

「ポリシー」タブの「YAML」で、サンドボックスの規則 (`network_policies`、プリセットと同じ形式) をタブいっぱいに出して、まとめて編集できます。適用していない編集は「一覧」に切り替えて戻っても残ります (「YAML」に「未保存」と出ます)。「YAML」を出しているあいだ、「一覧」には承認待ちの提案の数が出ます。「変更を確認」で YAML を確かめ、追加・削除・変更される規則を出します。「適用」で書いたとおりのポリシーになります。サンドボックスの作成時に決まる設定 (`filesystem_policy`、`landlock`、`process`) はその下に畳んで、読み取り専用で出ます。動いているサンドボックスでは OpenShell が変えないためです。プロバイダーの規則は YAML に入りません。

次のときは保存しません:

- YAML を読めないとき、追加・変更した規則が足りないとき (どの規則にも `endpoints` と `binaries` が要ります)
- 宛先がほかの規則やプロバイダーの規則と食い違うとき (OpenShell が拒否します)
- 読み込んだ後でポリシーが変わったとき (承認など。変わるとすぐ編集画面に出ます)。「読み込み直す」で今のポリシーを編集してください。編集していなければ自動で読み直します

保存の間に OpenShell で直接 (CLI など) 変えた分は、上書きされることがあります。そのときはタブに出ます。

プロバイダーの認証情報に結び付いた規則は、プログラムを変えられません。

承認した提案は承認済みのまま、プリセットも一覧に残ります。あとでプリセットを外すと、プリセットが入れたままの規則だけを外します。

## 承認する

承認ダイアログは宛先とエージェントの理由を先に示し、承認する前に絞れます:

- **読み取りだけ** か **書き込みも許可**: 読み取りだけは、並べたパス (空ならすべてのパス) への `GET`・`HEAD`・`OPTIONS` を許可します。書き込みも許可では、パスごとにメソッドを選びます (たとえば 1 つのパスへの `POST`。`*` は 1 区切り、`**` は以下すべて)。許可する書き込みはパスの上に並びます。提案に要るほうを選んだ状態で開きます
- **詳細**:
  - プログラム: そのパスだけ、バージョンを `*` にしたもの (更新しても使えます。バージョンがあるときの初期値)、同じ名前で始まるもの、フォルダーの下のすべて、すべてのプログラム。規則はそのプログラムが起動したプロセスにも効きます
  - 提案どおりの承認
  - **監査**: すべての要求を通して記録し、あとで記録から許すものを選んで「選んだものだけ許可して遮断に切り替え」ます。パスがまだ分からないときに使います

承認は規則の全体に効くので、ダイアログはそのすべてを示します:

- **注意** (選択肢の上): 提案が複数のプログラムやすべてのプログラム (`/**`) を挙げているとき、宛先を広げる設定 (`tls: skip`、`allow_encoded_slash`、`websocket_credential_rewrite`、`request_body_credential_rewrite`、`allow_uninspected_credentials`)、Iwato が動くマシンのループバックに届く宛先 (`host.docker.internal`、`host.wslc.internal`、`host.containers.internal`、`host-gateway` とそのアドレス。Iwato 自身と公開中のページが待ち受けています)。承認で許可するのは詳細のプログラムだけで、提案のほかのプログラムは許可しません
- **提案の内容** (まとめの下): すべてのプログラムと宛先を、設定・規則・拒否規則まで

Iwato が表示しきれない提案 (たとえばプログラム 8 個、宛先 20 個を超えるもの) や表示しない設定 (GraphQL、MCP、要求の署名) を含む提案は承認できません。却下するか、YAML で規則を書いてください。Iwato 自身のポートへの規則は、ダイアログ、手で追加する規則、YAML エディターのどれからでも拒否します。YAML エディターの確認では、ループバックに届く規則を示します。

承認は表示した版に対するものです: その間に提案が変わったとき (遮断が増えると OpenShell は提案を更新します)、Iwato は拒否して一覧を読み直し、もう一度たずねます。

OpenShell が拒否する選択肢は選べません (1 行で示し、理由は詳細にあります)。OpenShell は同じホスト・ポート・パスで検査の設定が食い違う規則を拒否し (endpoint ambiguity)、Iwato は送る前にそれを確かめます。それでもゲートウェイが変更を拒否したときは、理由を説明します。

プロバイダーの認証情報を付けた宛先の下への提案 (たとえば GitHub の `github.com` の下への `git push`) は、最初からその認証情報が付きます。一覧と承認の画面にそう出て、承認の画面で外せます。付いているプロバイダーの認証情報の宛先のホストへの提案では、承認の画面で付けるかを選べます (最初は付けません)。[プロバイダー](providers.md)

## プリセット

プリセットは名前の付いた規則のまとまりです。作成フォームで選ぶか、あとから「ポリシー」タブの「プリセット」で「入れる」「外す」ができます。外すと、プリセットが入れたままの規則だけを外します。作り直しても残ります。なくなったプリセット (Iwato から外されたもの、消した自分のファイル) には「プリセットが見つかりません」と出ます。その規則はふつうの規則としてポリシーに残り、「外す」は一覧から外すだけです。

Iwato のプリセット:

| プリセット | 許すもの |
|---|---|
| 「パッケージと Claude Code・Grok Build のダウンロード」 | どのプログラムからも読み取りだけ (GET・HEAD・OPTIONS と、読むだけの POST: npm の audit、レジストリーのトークン): npm、PyPI (uv の Python も)、crates.io、Rust のツールチェーン (rustup)、Go のプロキシ、RubyGems、mise、Node.js と Go の本体、GitHub のリリース・アーカイブの転送先と raw、Docker Hub と ghcr.io のイメージ。公開・アップロードは通りません。mise・claude・grok にだけ: mise のダウンロード (GitHub、mise-versions.jdx.dev)、Claude Code の更新・設定の取得 (downloads.claude.ai、platform.claude.com)、grok の版の確認・ダウンロード・更新 (x.ai、storage.googleapis.com) |

プリセットは認証情報を付けません。エージェントの API はプロバイダーとともに付きます。パッケージのプリセットは mise にだけ GitHub の読み取りを許します (mise が GitHub からダウンロードする)。

### 自分のプリセット

「ポリシー」タブの「プリセット」で、自分のプリセットを追加・編集・削除できます (「新しいプリセット」「YAML を編集」「削除」)。設定フォルダーの `presets/*.yaml` に保存し、一覧を開くたびに読み直すので、ほかのエディタで直しても構いません。読めないファイルは理由を出します。自分のプリセットの ID は `user:ID` になるので、Iwato のものを隠しません。

形式は OpenShell のポリシーの YAML の `network_policies` に、`id`・`label`・`note` と、任意の `params` を足したものです:

```yaml
id: my-preset
label: 自分のプリセット
note: 説明
params:                  # 任意。${repo} で使う
  - name: repo
    label: リポジトリ
    placeholder: OWNER/REPO
    pattern: '[A-Za-z0-9-]+/[A-Za-z0-9._-]+'
network_policies:
  allow_example_com_443:
    endpoints:
      - { host: example.com, port: 443, protocol: rest, enforcement: enforce, access: read-only }
    binaries: [/usr/bin/curl]
```

保存のときに、プロバイダーの規則と食い違わないことを確かめます。すべてのホストへの通信を許すプリセットは作れません。OpenShell はホストの `*`・`**` を受け付けず、ホストなしの `allowed_ips` の規則はほかの規則やプロバイダーと同じポートで食い違うためです。
