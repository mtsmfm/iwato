# Architecture

How Iwato is put together, by area and by file. Decisions and their reasons are in the ADRs ([`docs/adr/`](../adr/)); how to build, test and check things is in [development.md](development.md).

Principle: Iwato follows OpenShell's behaviour and improves only what is really inconvenient. New resource names, labels and image names start with `iwato`.

## Server and sandboxes

- `main.go`, `server*.go`, `sandboxes.go`: the exe and the admin UI's server. The console shows only the sign-in URL, a one-line notice when a startup check fails, and errors that need the owner, in English
- `fake*.go`, `fake_hooks.go`: the fake backend the browser checks drive (`serve -fake`): sandboxes, terminals, files, policies, providers and stand-ins for the sign-in pages (`/fake/...`), in memory, without running a command or a sandbox. `fake*.go` and the tests that use it (`*_fake_test.go`) are built only with the build tag `uitest`; their `init` sets `fakeHooks` (`fake_hooks.go`), through which `main.go` and the server reach the fake. Without the tag (release and `--debug` exes alike) `fakeHooks` is nil: there is no `-fake` flag and no fake route
- `update.go`, `update_*.go`, `web/update.js`: updating Iwato itself ([ADR 0015](../adr/0015-one-click-update-from-github-releases.md)). Published exes (`buildChannel`, `buildRepo`) check their channel's `iwato-build.json` (`scripts/build-meta.sh`) at start and every 6 hours: edge the release `edge` (another commit), release the latest release (a newer version). `GET /api/update` says whether the gateway's image changes (its digest against the gateway container's, `gateway.SameImage`) and which running sandboxes then restart; `POST /api/update/apply` downloads this OS's binary from the same release, checks its SHA-256 and that it runs (`version`), swaps it in (`exe.old` stays until the new build serves; one that fails before serving is replaced by the old exe again: on macOS and Linux the new build restores and execs it, on Windows the old process waits and does) and restarts on the same port (`IWATO_RESTART_LISTEN`): in place with exec on macOS and Linux, a new process in the same console on Windows. The page waits for the new build and reloads. `fake_update.go` is the fake's update, and in uitest builds `IWATO_UPDATE_BASE_URL` replaces GitHub
- `checks.go`, `checks_docker.go`: the startup checks (the engine: WSLc, or a Docker-compatible one with its version, VM and settings; the configuration). Each check is a level and keys with params (`checks.name.*`, `checks.detail.*`, `checks.hint.*` in `web/i18n.js`; the Docker install and start hints have `_linux` variants, `osHint`), shown in the settings (**Startup checks**, `GET /api/checks` runs them again). serve runs them before preparing; while the first check (the engine) fails, it serves the UI and waits: the list (`GET /api/sandboxes`) carries the failed check as `engine` and the page shows it in a banner with **Check again**, requests that reach the engine or the gateway (`needsEngine`, and `OpenShell.clients`) get 409 `engine_unavailable`, and the checks run again every 5 seconds. Once the engine passes, the gateway and the images are prepared as usual, without a restart. A missing CLI does not stop the exe either (`NewEngine` keeps the name and looks it up on each run). `serve -fake -fake-engine-down` shows the banner until **Check again**
- `openshell*.go`: one Iwato sandbox is one OpenShell sandbox (with the same name; all of them live in OpenShell's `default` workspace). Preparing the gateway, creating, stopping and deleting, terminals, approving and rejecting policy proposals (Policy Advisor), and editing the policy with its history (the same merge operation as `openshell policy update`)
- `recreate.go`: recreating a sandbox (the menu's **Recreate**, `POST /api/sandboxes/NAME/recreate`). It reads the providers attached in OpenShell and the rules of the latest policy revision (the effective policy without `_provider_*`), saves them into the settings (`Sandbox.Providers` and `Sandbox.Carry`), deletes the sandbox keeping its volumes, then creates and starts it with the same name and settings (the request may change only the GPU, refused as at creation where none is available). The home volume's name follows from the sandbox name and the path (`persistVolume`), so the same volume is attached (only what is under the home survives: paths outside the home that earlier versions persisted (`Sandbox.LegacyPersist`, `persist` in the settings) are dropped, and their volumes remain in the volumes screen (**Volumes**)). Rules are restored one per update, each after the same checks as an edit (`checkOps`); a refused rule is reported and the rest continue. If it fails halfway, `Carry` stays and the next recreate or start restores it (then it only adds missing rules, never removes or changes any; only right after creation does it drop preset rules the old policy did not have and replace differing rules). e2e: `openshell_recreate_e2e_test.go`
- `reset.go`, `web/reset.js`: **Delete everything** at the bottom of the settings (`POST /api/reset`, confirmed by typing `reset`, plus CSRF; it returns when done, and `GET /api/reset` reports progress). It deletes, through the gateway, the sandboxes (those in the settings and those in the gateway), then the volumes still carrying Iwato's labels, the gateway (`gateway.Remove`: containers with the `iwato.gateway.image` label, the state volume, the network, the image), what the driver left in its namespace (`wslc.RemoveAll`), the standard image and replaced images recorded in `images.json`, and the secrets in the config folder (certificates, Tailscale (logged out first), Web Push, logins, app passwords) with, on macOS, the Keychain key of the protected files (`protect.DeleteKey`), and removes the sandboxes and scopes from `iwato.json`. The user's presets and profiles and the settings are deleted only with `ownerFiles`. First it cancels the OAuth flows in progress (`cancelOAuthFlows`: their context ends, a later callback is refused, and `handOverGrant` gives the gateway nothing once its context ended), before it claims the sandboxes, and again after the logins are gone. Afterwards it prints a new login URL and prepares the driver and gateway again (as on a first start). It refuses while images or the gateway are being prepared
- `sessions.go`, `web/sessions.js`: the browser logins. The login URL's single-use token (`POST /api/session`) gives an HttpOnly, SameSite=Strict cookie and a CSRF token; `sessions.json` keeps each session's SHA-256 with its CSRF token, expiry, creation, last use (recorded at most once a minute) and User-Agent (older files without the last three still load). The settings' **Signed-in devices** lists them (`GET /api/sessions`) and signs this browser out (`POST /api/sessions/logout`), another (`POST /api/sessions/ID/revoke`, ID a prefix of the hash) or all others (`POST /api/sessions/revoke-others`), with CSRF. A session that ends (also by expiry or reset) closes its terminals' WebSockets (4401)
  - The cookie is not bound to the port: browsers send cookies for `127.0.0.1` to every port on it, so a server the owner opens at another `127.0.0.1` port receives the admin cookie. Browsers' requests from that origin are refused (Host, Origin and `Sec-Fetch-Site` checks, SameSite=Strict, CSRF on every POST and WebSocket), but a program holding the cookie can send its own requests: the cookie alone answers GETs, including `GET /api/session` with the CSRF token. Neither the `__Host-` prefix nor `Secure` is available on plain http. The cookie name is random per configuration (`iwato_` + 16 hex digits), and a leaked cookie can be revoked in the settings. The tailnet origin (`-public-origin`, https) sets the cookie with `Secure`
- `autostop.go`: every sandbox stops after its last terminal ends (no setting; an old `autoStop` field in `iwato.json` is dropped). When a terminal session Iwato holds ends (`OnTerminalEnd`), it stops the sandbox if the daemon's list has no terminal left (`TerminalsIdle`; every daemon version answers it, so no recreate is needed; a sandbox without the daemon already stops when its main terminal ends, so nothing is done there). A terminal connection or any other operation (`beginOp`) before the stop cancels it, and the page shows a stopped sandbox's placeholder instead of its last screen. If terminals remain, the ones without a session are reattached to see their end. The list's `autoStopAt` lets the page show "stops in about N seconds"
- `agent_files.go`: on every start, execs as the sandbox user and places `~/.claude/CLAUDE.md` (`@/AGENTS.md`) and `~/.codex/AGENTS.md` (a link to `/AGENTS.md`) in the home, only when absent (neither Claude Code nor Codex reads `/AGENTS.md` by itself). It is an exec rather than the driver's staging (`wslc container cp`, as root before creation) because an exec sees the real filesystem with the persisted volume attached, with the user's permissions, can check without following links, and can silently skip whatever does not fit in any image
- `agent_urls.go`, `internal/agentsmd`: the generated `/AGENTS.md` ([ADR 0016](../adr/0016-no-helper-commands-for-agents.md)). In the standard image it links to `~/.iwato-agents.md` (directly in the home: no directory on the way can keep the writers out), which `iwato-entrypoint serve` writes at start from `/etc/iwato/AGENTS.md` and the section after `agentsmd.Marker` it already had. The ingress manager builds that section, "Your URLs" (the current provider's URL form with `PORT`: local, or the tailnet one once the node is connected; none when publishing is off or the sandbox is not exposed), on each sync (start, stop, settings, every 15 seconds) and writes the whole file into running sandboxes through an exec when it changed or the sandbox started again, and again on the next sync after a failure (only into a home of the user's own and when `/AGENTS.md` links there; a temporary file renamed over it, replacing a link in its place)
- `term_env.go`: the terminal environment variables Iwato sets: `CLAUDE_CODE_SCROLL_SPEED=3` (Claude Code scrolls 1 line per wheel report in terminals it does not know), `TZ` (below), and those that depend on the attached providers (`GROK_AUTH_PROVIDER_COMMAND` with the xAI subscription, `CLAUDE_CODE_OAUTH_SCOPES` with the Claude sign-in). OpenShell decides a sandbox's environment only at creation, so on every start, and after each attach or detach on a running sandbox, Iwato execs as the sandbox user and writes `~/.config/iwato/env` (only when the content differs; without following links). Its lines export a setting only when the provider's variable exists and the setting is not set yet (`GROK_AUTH_PROVIDER_COMMAND` when `XAI_OAUTH_TOKEN` exists). A provider of the retired setup-token type also gives `CLAUDE_CODE_OAUTH_TOKEN`, so the scopes line is written only while a sign-in provider is attached. The supervisor puts provider variables into the first process and each exec, so attaching or detaching takes effect on restart (for extra terminals, when the supervisor picks it up). The standard image's `/etc/iwato/env.sh` reads it (from `/etc/profile.d` and `/etc/bash.bashrc`, before the user's `~/.profile` and `~/.bashrc`, so those can override it). Only on the first start of a new home volume may the first shell start before Iwato writes the file. The creation environment (`sandboxEnv`) holds only what never changes (HOME, IWATO_PERSIST (the home alone; only what is under the home survives), COLORTERM)
- `timezone.go`, `timezone_other.go`, `timezone_windows.go`, `timezone_tables.go`: the sandboxes' time zone (`iwato.json` `timezone`, `/api/timezone`, the settings' 「タイムゾーン」): `""` follows the host's (macOS/Linux: `TZ`, the `/etc/localtime` link, `/etc/timezone`; Windows: the registry's `TimeZoneKeyName` through CLDR's windowsZones table), else an IANA name; unknown zones are UTC (logged). Names are checked with Go's embedded tzdata and turned into current IANA names (CLDR's aliases: Ubuntu's tzdata lacks the old links). The zone goes into `~/.config/iwato/env` as a default `TZ` (none for UTC); a change rewrites it in the running sandboxes, for terminals opened afterwards. `scripts/gen-timezones.cjs` makes the tables from CLDR

## Policy and presets

- `presets*.go`, `presets/`: network presets (Iwato's are `presets/*.yaml`, embedded; the user's are `presets/*.yaml` in the folder of `iwato.json`; the format is at the top of `presets.go`. Ids: Iwato's are the `id` in `presets/`, the user's are `user:ID`). At creation they go into the first policy; later `POST /api/sandboxes/NAME/presets/apply` and `remove` attach and detach them through the same merge and checks as an edit, and they are kept in `Sandbox.Presets` (so they survive recreating). When OpenShell folds a rule into an existing rule for the same destination (merge.rs add_rule) it can no longer be removed, so Iwato predicts that and refuses before applying, and re-reads afterwards and reverts. Hosts that a provider's credentials reach belong to the provider (ADR 0006) and cannot be written in user presets (`credentialHits`). A file's errors and a preset's parameter errors are coded (`preset_*`, with English text for the log); the list's unreadable files carry `code` and `params`. Editing user presets as YAML in the UI: `presets_user.go` (`/api/presets/user[/FILE]`). `TestBuiltinPresetsFitTheProviders` checks that all of Iwato's presets together with all providers cause no ambiguity, and `openshell_presets_e2e_test.go` that the gateway accepts them
- `endpoint_ambiguity.go`, `policy_prediction.go`: a port of OpenShell's endpoint ambiguity check (rules that hit the same host, port and path but disagree in their inspection settings are refused; `crates/openshell-policy/src/ambiguity.rs`), and applying a change the way merge does (adding the providers' rules too) to check it in advance. The approval dialog's unavailable choices, refusals of hand edits and of attaching (with how to fix them), and the reading of the gateway's refusals come from here. The server sends them as a code (`ambiguous_*`, `gateway_ambiguous`, `credential_uninspected`, `provider_attach_refused`, and `provider_scope_conflict` for a provider scope change) with the pairs (`ambiguities`: each with `diffs`, field and value tokens; `gatewayAmbiguities`) and the conflicts, and `web/refusals.js` words them in the page's language; the Japanese text in `error` is the fallback

### The policy tab

The policy tab (**Policy**) shows three lists from OpenShell's data alone (Iwato stores nothing):

- Pending (承認待ち): the draft's pending chunks
- Approved (承認一覧): the effective policy from GetSandboxConfig. `_provider_*` rules are read-only. A rule tied to an approved chunk by rule name and program can be undone (**Undo** = UndoDraftChunk plus removing the widened glob); an approved chunk without a rule gets **Put the rule back and undo** (`openshell_policy_lists.go`). For inspected destinations, the requests the audit let through and the requests that were blocked are shown from the gateway's sandbox log (the last 2000 lines, cached 5 seconds), because L7 denials do not become proposals (`openshell_audit.go`)
- Rejected proposals (却下した提案): rejected chunks (the count at rejection time goes into the rejection reason)

The tab's header (sticky while the lists scroll; the panel is its own stacking context, so the header stays under the panels opened over the tab, such as **Providers**) switches between the lists (**List**) and the YAML editor (**YAML**), which fills the tab; the choice is in `localStorage` `iwato-policy-view`. Unapplied YAML edits are kept across switches (**Unsaved** on the switch) until applied or reloaded; while the YAML shows, **List** carries the count of the agent's waiting proposals, and when the listed policy's version passes the loaded one the editor says so (and reloads by itself when there are no edits). The YAML editor (`policy_yaml.go`, `GET`/`POST /api/sandboxes/NAME/policy/yaml`) edits the latest revision's `network_policies` as a whole, in the presets' format; the rest of the policy (filesystem, landlock, process) is shown read-only, because OpenShell refuses changing it on a live sandbox (`validate_static_fields_unchanged`: landlock and process must match the creation policy, filesystem may only gain paths, which Landlock would apply only at the next start). Saving sends the whole policy (UpdateConfig with `policy`, the other parts as the latest revision has them), not merge operations, which would fold a new rule into an existing rule with the same endpoint. Rules left as they were are sent as the gateway gave them; a changed rule keeps `advisor_proposed` on the endpoints it kept. Before applying, the added and changed rules are checked as edits are: their shape, endpoint ambiguity with the other rules and the providers' (`newAmbiguities`), and the providers' hosts (ADR 0006: no added or changed endpoint may reach an attached provider's credential, inspected or not, unless the rule had it already, as it was, for no more programs). A save without `apply` returns the difference (added, removed, changed rules), which the page shows for confirmation. Concurrency: the save names the revision it was loaded at and is refused (`policy_yaml_stale`) once the latest is another; the gateway's `expected_resource_version` is the sandbox object's version, which policy revisions do not change, so Iwato compares the versions itself, under the sandbox's policy lock (below). A change made directly in OpenShell between that check and the update is replaced: afterwards Iwato reads the latest version again, and when it is not the loaded one plus one the answer carries `policy_yaml_overwritten`, which the page shows. `Sandbox.Presets` and the approved chunks are left as an edit leaves them. e2e: `openshell_policy_yaml_e2e_test.go`

Proposals and rules for hosts that an attached provider's credentials reach belong to the provider (ADR 0006, `proposal_scope.go`): for a provider with its own profile, approving widens the provider's scope (`POST .../proposals/scope`), and once the sandbox has applied it the chunk is rejected with a "retry" reason (OpenShell's approval would add the rule to the policy). Proposals that cannot become a scope are approved as rules, with the reason and a warning that the token rides along. Existing rules get the "Provider X's destination" mark. Rules written by hand (an added rule or methods and paths, and the YAML editor) that reach a credentialed endpoint of any profile Iwato knows, attached or not (`credentialTargets`, as presets are checked), go in only with the owner's confirmation, as an approval that keeps a provider's token does: the server answers 409 `policy_provider_host` with the endpoints, the providers, whether one has a scope (then the page suggests the scope as the narrower way) and a token (`confirmToken`, a hash of the sandbox and the exact plan: the edit, or the YAML's version and rules); the retry carries it, so another plan needs its own confirmation. A rule's endpoint already there may stay as it is (for the same or fewer programs) without asking; a rule with an endpoint bound to a credential (`credential_binding`) keeps its programs (refused). The check fails closed (`provider_unverifiable`) when the policy cannot be read. Attaching a provider while a rule lets its credential reach more than the provider's own rule allows (`beyondScope`: each request the rule's endpoint lets through must be one the provider's endpoint lets through; an audited or uninspected endpoint lets everything through) is asked the same way (`provider_attach_beyond_scope`, with the endpoints in `beyond`; `providers/fix` with that token removes them); rules already there and unchanged never stop a sandbox from loading or starting.

What an approval binds to (`proposal_guard.go`): each listed proposal carries a digest (sha256 of the chunk's program, rule name and proposed rule); approve, reject and `proposals/scope` send it back, and the server refuses with `proposal_changed` (409) when the chunk is no longer that one, checked again right before the decision. The approve dialog always sends the program it shows (`scope.binaries`); a scope without programs is refused when the rule names some (`scope_binaries_missing`), and a scope that only repeats the rule's own programs approves it unchanged (no edit). The server approves only a rule the page shows whole: the proposals list sends `limits` (programs, endpoints, ports, rules, deny rules, allowed_ips), and a rule beyond them, with longer values than the page shows, or with settings the page does not render (GraphQL, MCP, JSON-RPC, signing, protocols other than rest and tcp, matchers other than method and path) is listed with `unshown` and refused (`proposal_unshown`), as proposed or narrowed. Each endpoint carries its other settings (tls, path, rules and deny rules per endpoint, allowed_ips, credential binding, the widening flags); the dialog lists the whole proposal under **The proposal** and warns in the main view, styled as the writes, of several programs or `/**`, the widening flags, and destinations that reach the host's loopback (`hostGateways`: WSLc's, Docker's and Podman's names and addresses, sent with the list; a host glob or an allowed_ips entry containing an address counts). A rule with an endpoint on Iwato's own port (`iwato_port`) is refused from approvals, restores, hand edits and the YAML editor; the YAML editor's check returns `gateways`, which its confirmation names, and the hand-edit form warns as the dialog does.

Iwato's policy writes are serialised per sandbox (`policy_lock.go`): an edit, the YAML editor, approving, rejecting, undoing and restoring proposals, presets, a recreate's carried rules, attaching, detaching and fixing providers, and a provider's scope change or custom profile update (the sandboxes it is attached to) hold the sandbox's lock from reading the policy and the providers until the gateway has the change. Order: `providerMu` first, then the sandboxes' locks in name order. Changes made directly in OpenShell (its CLI, a proposal decided there, the supervisor) are not covered.

The draft keeps growing without deleting chunks, so each read fetches only pending chunks; approved and rejected ones are kept in memory per sandbox (`openshell_draft.go`) and re-read when draft_version changes, when Iwato makes a decision or an undo, and after 1 minute (decisions made elsewhere, such as the CLI, show up at most 1 minute late). While open, the tab reads with the list refresh (every 10 seconds), and every 2 seconds while something is waiting to apply and for 30 seconds after an owner action. Notifications read only pending chunks. The fake backend runs the same code against a fake gateway (`fake_policy.go`). The approval dialog's candidates, expansion and summary are computed in `web/approve.js` (no DOM; each proposed endpoint carries its access preset and enforcement, so approving as proposed shows the writes a preset or audit allows, and a reach it cannot tell is shown as a write) and tested by `node scripts/ui-behavior-tests.cjs`. Browser checks: see [development.md](development.md).

## Providers

- `providers*.go`, `openshell_providers.go`, `profiles/`: OpenShell providers. Iwato's profiles (`profiles/iwato-github.yaml` etc., written in OpenShell's YAML format as they are, so `openshell provider profile lint -f` accepts them; their paths match the standard image; display names and the like for the UI are in `providers_profiles.go`; how to lint is in [providers.md](providers.md)) are imported during preparation and attached and detached per sandbox. Preparation only imports and updates them, never deletes: a profile no longer shipped stays in gateways that have it, so its providers keep working and the page lists them under **Other** like CLI-imported ones, to detach and delete. Attaching or detaching on a running sandbox shows **Restart pending** until it restarts. Attach and detach return as soon as the gateway accepts them; until the running sandbox applies them (the supervisor polls about every 10 seconds) the receipt is kept in the settings and checked on each list, showing **Waiting to apply**. Scopes (ADR 0006, ADR 0014, `providers_scope.go`): a provider of any built-in profile gets its own profile `BASE-for-NAME` (e.g. `iwato-github-for-NAME`) at creation, the OAuth ones too (`oauth_grant.go`; OpenShell cannot change a provider's type later), which Iwato generates from `providerScopes` in the settings and imports. GitHub's modes are read-only, repositories (plus named GraphQL mutations) and full; the others' are read-only (the profile as shipped) and full (`access: full` on the same endpoints). Atlassian's are tools (default; `providers_scope_atlassian.go`: the endpoint becomes `protocol: mcp` with `allow_all_known_mcp_methods` and one `tools/call` rule for `atlassianReadTools` plus the named write tools) and full; its providers saved as read-only before mode tools keep the shipped profile (every tool) and show as full. Providers of a shared built-in profile (made before) stay as they are, marked as legacy. The scope of a base no longer shipped (`retiredBases`: `iwato-claude`, Claude Code's setup token) stays in the settings unchecked and unrendered, and goes with its provider's profile when the provider is deleted. The approve dialog turns a write on a non-GitHub provider's endpoints into mode full (`writeField` in `proposal_scope.go`), and an MCP proposal on an Atlassian provider in mode tools into the tools it names (`toolsField`). Changing the scope updates the profile, which reaches running sandboxes without a restart; **Waiting to apply** comes from observing `GetSandboxProviderStatus` (no receipt). Custom profiles (`providers_custom.go`) are `profiles/ID.yaml` in the folder of `iwato.json` (ids starting with `iwato-` are not allowed). e2e: `openshell_scope_e2e_test.go`
- `atlassian*.go`: Atlassian's MCP (`iwato-atlassian`). Iwato.exe gets the authorization with OAuth (DCR, PKCE, a 127.0.0.1 redirect or pasting from a phone), hands the refresh token to the gateway and lets it refresh (oauth2_refresh_token). Iwato does not keep the refresh token (ADR 0009). Handing it to the gateway: `oauth_grant.go` (shared with xAI and Claude)
- `xai.go`, `fake_xai.go`: the xAI subscription for Grok Build (`iwato-grok-subscription`). Iwato.exe signs in at auth.x.ai with a device code login using Grok Build's public client (the same steps on a PC or a phone) and hands the refresh token to the gateway. The sandbox's grok receives the placeholder through `GROK_AUTH_PROVIDER_COMMAND` (`term_env.go` above). e2e: `openshell_grok_e2e_test.go`
- `claude_oauth.go`, `fake_claude.go`: Claude Code with a Claude account sign-in (`iwato-claude-subscription`, the only Claude Code type). Iwato.exe signs in with Claude Code's public client (authorization code, PKCE, state; a `http://localhost:PORT/callback` redirect on the PC, or Claude's manual-code page whose `CODE#STATE` a phone pastes) and hands the refresh token to the gateway. The sandbox's claude gets the placeholder in `CLAUDE_CODE_OAUTH_TOKEN`

## Files, editor and paste

- `files.go`, `internal/dav`, `web/files.js`: the files tab (**Files**), the sandbox's home `/home/dev` as a network drive. Iwato serves WebDAV at `/dav/` and translates it to the sandbox's SFTP behind the scenes: the daemon's SFTP server when the daemon has `sftp` (rooted at the home; one channel = one TTY-less exec, `internal/openshell/client/daemon_sftp.go`), otherwise OpenShell's SFTP (the supervisor's `sftp` subsystem over the same gateway relay as terminals; rooted at the working directory, and the files tab and the editor show `files.rootNote` / `editor.rootNote`, "Opens the working directory ({path})."). `FilesRoot` (`openshell_files.go`) says which. Authentication: app passwords (Basic) and a secret URL for this PC (direct from 127.0.0.1 only). Research and real-hardware checks: [files.md](files.md)
- `editor.go`, `web/editor.js`: the editor tab (**Editor**) opens and saves text files under the same root as the files tab (the home). `GET .../editor/root` gives the root and whether `~/work` exists (the folder starts at `work` when none is remembered), `GET /api/sandboxes/NAME/editor/files?dir=` the list, `GET` and `POST .../editor/file` read and save, `GET .../editor/dir?path=` one folder of the tree, `GET .../editor/raw?path=` the image preview, `GET .../editor/media?path=` audio and video. Reads and writes use the same SFTP pool as the files tab; saving uses `internal/dav`'s `WriteFile` (write a temporary file and replace, keeping the permissions), and returns 409 (`changed`) when the SHA-256 differs from the content when opened. The quick-open list is `rg --files` run in an exec as the sandbox user (`ListFiles` in `openshell_files.go`), or an SFTP walk without rg. The tree reads only opened folders with SFTP ReadDir (folders first, by name, up to 2,000 entries; links are not followed, and only links to files can be opened; `editorSkipDirs` are marked and not expanded even when showing an opened file). Opened folders are remembered per sandbox by the page and localStorage. The text is CodeMirror 6: `web/vendor/codemirror.js`, one minified script built by `scripts/build-codemirror.sh` from `scripts/codemirror/` (pinned packages in its `package-lock.json`, `entry.mjs` choosing the pieces and the languages) and committed. `editor.js` loads it with a script tag the first time an editor panel or a YAML box shows, and keeps one view per panel and one `EditorState` per open file (text, selection, undo history); the highlighting follows the file's name (`languageOf`), with colours from `--code-*` in `styles.css` and the terminal's font. The YAML boxes (the policy as YAML, the owner's presets, provider profiles) are the same setup through `IwatoCode.mount` (`editor.js`): a textarea until the bundle has loaded, CodeMirror after. On wide cards the page can show the editor and the terminal side by side (`web/app.js`, `layoutTabs`; editor left, terminal right, the divider and the choice in `localStorage` `iwato-split`; the terminal's size is sent once the divider or the window rests); narrower cards and phones keep the tabs. When the bundle does not load (and in `ui-behavior-tests.cjs`, which has no DOM) a textarea takes its place with the same open, save, stash and conflict handling. The bundle needs no eval and injects its styles as `<style>` elements, which the page's CSP (`style-src 'self' 'unsafe-inline'`) allows. Images (known by name, or text loads that return 415) are a read-only preview whose `<img>` points straight at the raw route (not a same-origin blob: URL, so that raw's CSP applies even when opened alone). raw serves only images detected by content (`editorImageType`: PNG, JPEG, GIF, WebP, BMP, ICO, AVIF, SVG) up to 20 MB, with their Content-Type, `nosniff` and the CSP `default-src 'none'; style-src 'unsafe-inline'; sandbox`, and 415 for anything else (so Iwato's origin never serves the sandbox's HTML or JS). Audio and video (by name, `mediaKind`) play in an `<audio>`/`<video>` of the media route, which takes the type from an extension allowlist (`editorMediaTypes`; 415 otherwise) under the same headers and streams the file with `http.ServeContent` (Range) over `internal/dav`'s `OpenRead`, the WebDAV GET's buffered reader: the SFTP lease is held while the response is read, with no time limit, and released when it ends; closing the tab drops the player's request. A Markdown file can show a preview instead of the text or beside it (`localStorage` `iwato-editor-view`): marked (`web/vendor/markdown.js`, built by the same script and lock from `markdown.mjs`, loaded when a preview first shows) renders it, raw HTML escaped, into an `<iframe srcdoc>` whose `sandbox` has only `allow-popups allow-popups-to-escape-sandbox` (no scripts, an opaque origin) and whose CSP is `default-src 'none'; img-src data:; style-src 'unsafe-inline'`. Only http(s) links are links. Relative images are read by the page through raw (the iframe has no session) and passed in as data: URLs; external images show their alt text, so the file cannot make the browser contact other hosts
- `paste.go`: pasting images into a terminal (`POST /api/sandboxes/NAME/paste-image`). It writes into `.cache/iwato/paste/` under the root (the home) through the same SFTP pool as the files tab and returns the absolute path (which the page pastes). Details: [files.md](files.md)

## Publishing ports

- `ingress*.go`, `openshell_ingress.go`, `internal/ingress`, `web/ingress.js`: publishing a sandbox's ports. The default is `internal/ingress/local` (ADR 0003): `http://<port>.<sandbox>.localhost:<Iwato's port>/` is received on the same listener as the admin UI and split off by the first request's Host, before the admin UI's Host check (`local.Split`; only known sandboxes, names that are DNS labels, the right port, and direct connections from this PC; anything else gets the admin UI's 403. No authentication; HTTP and WebSocket only). Tailscale is optional (`"provider": "tailscale"`; the tsnet nodes are `internal/ingress/tailscale`, the secret (DPAPI on Windows, a key in the Keychain on macOS) is `internal/protect`). The layers (Route / Backend dialer / Auth / Provider / Protocol) are in `internal/ingress`; ForwardTcp is `internal/openshell/client/forward.go`. The UI is the settings (this PC only, Tailscale, off) and the **Ports** tab. Design and real-hardware checks: [ingress.md](ingress.md)

## Notifications

- `notifier.go`, `presence.go`, `webpush.go`: Web Push notifications (agents' proposals and stopped terminals). They are sent only when no device has a page open and in use (shown, and used within 5 minutes; the page reports this with `POST /api/presence`); those arising while in use are dropped. Stopped terminals are also returned in the list (`stopped`), and the UI marks them until they are viewed. Terminals are judged from the screen ([ADR 0017](../adr/0017-terminal-done-from-the-screen.md), [0018](../adr/0018-ticking-terminals-are-alive.md)): every 5 seconds (proposals every 15) the notifier compares each screen's rows by their letters, leaving out changes within 5 seconds of a client's input (`termsync.Activity`: keys, mouse, paste, resize, attach, detach) and rows that keep changing alone. Changes in 3 polls over 20 seconds are work; a minute without change (or a known agent's working hint going away, `workingHints`) is done, but not while the raw screen changes in 3 of the last 4 polls (counters, spinners: alive), pushed unless the screen equals the one when the owner last left. Bells and OSC 9/777/99 notifications (`termsync.Alert`) outside the input window push at once, once a minute per terminal. A terminal done or rung while in use only gets the mark

## Images and the driver

- `engine.go`, `images.go`: calling the engine's CLI (wslc.exe on Windows; on macOS and Linux the `docker` CLI of a Docker-compatible engine, chosen when `iwato.json` has no `wslc`; [ADR 0002](../adr/0002-macos-docker-compatible-runtime.md)). `internal/dockercli` turns wslc's commands into docker's (only `inspect --format json` differs). On Docker, volumes must be `local` without options and carry the labels the Docker driver's resource admission requires (`attachLabels`); `checks_docker.go` checks the engine (below). Also pulling and building the standard image (`sandboximage/`). What goes in it: [ADR 0004](../adr/0004-standard-image-contents.md). A default development build pulls ghcr.io's `edge` (published by `.github/workflows/image.yml` on pushes to main; PRs that touch the images only build them) only when it has none locally, and updates only on request (`imageMoves`, `UpdateImage`; `GET /api/images` and `POST /api/images/update` in `image_update.go`; in the UI, the settings' **Update the standard image** and the recreate dialog's **Pull the latest image first**). `scripts/build-exe.sh --local-images` builds locally; `--images` (releases, and the published edge exes with `--image-tag edge`) also pulls the gateway image (`pullsGatewayImage`), pinned by digest (`imageDigests`), so it does not move
- `internal/openshell/wslc`: OpenShell's WSLc compute driver (a port of the Docker driver; [ADR 0007](../adr/0007-in-house-wslc-compute-driver.md)). The image convention ([ADR 0005](../adr/0005-sandbox-image-convention.md)) carries the daemon and the Policy Advisor guide, so the driver does not place them at creation (only the daemon for old sandboxes, `-legacy-term` below). The difference that a writable volume may be the working directory itself is kept for images whose WORKDIR is the home (the earlier standard image). `e2e.sh` tests it with a fake wslc (`fakewslc`) together with the official gateway and sandbox
- `internal/openshell/gateway`: the gateway's image and startup. One image for both engines: on WSLc the entrypoint relays the driver socket to Iwato's WSLc driver; on a Docker engine (`Options.DockerSocket`, `COMPUTE_DRIVER=docker`) the gateway runs upstream's Docker driver with `gateway-docker.toml`, on the engine's socket mounted into the container (`/var/run/docker.sock` in the engine's VM; rootless Docker's own socket on Linux, `dockercli.Socket`). The supervisors use the engine's host network and reach the gateway on 127.0.0.1:17670, where its port is published; the driver keeps each sandbox's state in the state volume (`XDG_STATE_HOME`). Sandboxes get `driver_config.docker` with the home volume and a 1 GiB `/dev/shm` tmpfs (`OpenShell.driverConfig`). e2e on Docker: `openshell_docker_e2e_test.go` (`IWATO_E2E_DOCKER=1`, the `docker` job of `e2e.yml`). The Dockerfile checks the OpenShell release tarballs against SHA-256 pinned per release and architecture before extracting them, and both drivers use the official runtime images pinned by digest (`wslc.DefaultSupervisorImage`, `DefaultSandboxImage`; the same refs in `gateway-docker.toml`); [bumping them](development.md#bumping-pinned-versions)

## The in-sandbox daemon

- `cmd/iwato-entrypoint`, `internal/termd`, `internal/rootsftp`: Iwato's daemon in the sandbox ([ADR 0005](../adr/0005-sandbox-image-convention.md), [ADR 0012](../adr/0012-iwato-entrypoint-in-the-image.md); formerly `iwato-term`). It owns the PTY and process of every terminal (main included) and keeps the last 1 MiB of output. `iwato-entrypoint sftp -root /home/dev` serves an SFTP server confined to the home (`os.Root`: neither `..` nor links get out) over stdin/stdout
- The standard image carries it at `/usr/local/lib/iwato/iwato-entrypoint` (`scripts/build-entrypoint.sh` builds it from the same commit, and `.github/workflows/image.yml` and `release.yml` put it into the image; `--local-images` puts in the one embedded in the exe, `internal/termbin`) and names it with the label `iwato.entrypoint`. New sandboxes of a labelled image are created with `iwato-entrypoint serve` as OpenShell's first process (no TTY), and Iwato talks to it over the stdin/stdout of a TTY-less exec of `attach` (`internal/openshell/client/held.go`; a message is one type byte plus a length). On reconnect the output is replayed, and the size is shrunk by one row and restored to force a repaint
- The socket is in `/tmp/iwato-term-$UID/` (0700, the peer's uid is checked; the old name is kept so both binaries reach the same daemon), one per key (sandbox name) (flock)
- Versions and capabilities: list and hello return the daemon's version, capabilities (`terminals`, `sftp`) and path (version 1 returns none: terminals only). Iwato uses what is there and falls back for the rest (files use OpenShell's SFTP, and the files tab and the editor say they show the working directory). Compatibility is broken only by raising `termd.MinVersion`
- Iwato checks once per sandbox start (`list -spawn`; in a sandbox where the daemon is not the first process, this starts it; it tries the image's path and then the old path). Sandboxes without it work as before (main is the first process, the others are TTY execs)
- Sandboxes created before this mechanism (first process `/usr/local/lib/iwato/iwato-term`) get the exe's daemon placed at the old path by the WSLc driver on every start (only while stopped: OpenShell pins the hashes of the executables of a connecting process and its parents, so replacing it while running would cut the network of the terminal's programs) (`-legacy-term`, `internal/termbin`; not present in `go test` or plain builds). Only when that daemon is older than Iwato's does the UI show **Update** (fixed by restarting the sandbox). The image's daemon does not change until the sandbox is recreated
- When Iwato starts, it reattaches to the terminals of running sandboxes in the background (for notifications; for 5 seconds after attaching it ignores the screen, and takes the screen right after attaching as the baseline; bells replayed before are dropped)
- Do not set `PR_SET_DUMPABLE` to 0: OpenShell then blocks the network of all its descendants

## Terminal emulation

- `internal/hostterm`: the terminals Iwato holds (screen and scrollback)
- `internal/screen`, `internal/termsync`, `web/term.js`: the terminal emulator and how the screen is sent to the browser
- `web/links.js`: the http(s) URLs in the terminal's text (screen, history, clicks). Where a URL ends follows UTS #58 (its data generated by `scripts/gen-linkterm.cjs`), except that CJK sentence punctuation (`、。！？，．`), box drawing and backticks end it at once and a `?` at its end is left out

Only `internal/screen` on Iwato's side holds the terminal state; `internal/termsync` sends diff frames and history pages to the browser (`/ws/NAME`). The browser (`web/term.js`) does not interpret output. `internal/termsync`'s test (`TestRandomOutput`) is a model that applies frames the same way the browser does, and checks that after random output, resizes and screen switches it matches the server's state. To look at screen text from Go tests, use `internal/termsync/termsynctest`. A client gets frames until 6 of them, or 64 KiB, await its ack. Its input and resizes wait in a queue of their own, so that a program slow to read them does not hold up the acks. Browser checks: see [development.md](development.md).

Output from the sandbox cannot grow the state without bound. The history keeps 50,000 lines or 16 MiB, the title and a notification's text 4 KiB, one OSC string 1 MiB (an OSC 52 clipboard write, 768 KiB once decoded), a URL 8 KiB (OSC 8 links and OSC 6464 opens), the style table 65,535 styles. The OSC 8 link table holds 4 MiB (URLs plus 64 bytes per entry) and 65,536 links: when a new link would pass either, the links no cell of either screen or the history uses (through its style) are evicted, then, until the table is at half, the least recently used ones other than the pen's. Link ids are never reused, so a cell whose link was evicted shows no link (termsync sends its style with link 0), never another URL. Screen updates are not queued per client (a frame is the difference from what the client has), but events are: while a client lags, its queue keeps only the latest clipboard write, up to 16 links to open, and 1 MiB of text; the rest is dropped. A client's input waiting for the program is bounded to 1 MiB (reading more of it waits).

ASCII is drawn as text in the font; other characters, the cursor and the composing text are placed on a grid of cells measured from the font (`measure` in `web/term.js`). The cell is measured again on every fit (resize, a font that finished loading, the page shown again); a terminal that is not laid out keeps its cell until it shows, so a font that arrives while it is on another tab does not leave a guessed width behind. A link on the screen is taken from the cell under the pointer (its OSC 8 link, or a URL `links.js` found there), not from the element on top, and opens on release over the link pressed: the browser sends no click when a redraw replaced the element under the press.

### Screen keyboard and rows

When the on-screen keyboard opens on a phone, the terminal's row count does not change (holdRows in `web/app.js`). When rows shrink, Claude Code repaints its last lines, but lines the terminal pushed into the scrollback stay there when the rows come back, so the history shows the same lines twice. Besides `node scripts/ui-behavior-tests.cjs`, check in a real browser after changing anything around the keyboard or the page layout (see [development.md](development.md)).
